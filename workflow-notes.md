## Core Workflow Concepts
* **Issues:** Used to define tasks, acceptance criteria, and track the overall goal of the project before coding begins[cite: 11].
* **Branches (`feature/github-ai-workflow`):** Isolate development work away from the default branch (`main`), keeping production code clean and stable[cite: 11, 12].
* **Commits:** Incremental, atomic checkpoints of code changes with descriptive, meaningful summaries (avoiding vague labels like "update")[cite: 12].
* **Pull Requests (PR):** Proposed merges from a feature branch back into the base branch (`main`), enabling code review, discussion, and verification against acceptance criteria[cite: 10, 11].
* **Default Branch (`main`):** The primary, stable integration branch of the repository where completed and reviewed features are ultimately merged[cite: 10, 11, 12].

## Workflow Item Relationships
The **Issue** establishes the scope and required acceptance criteria[cite: 11, 12]. A dedicated **Feature Branch** isolates all new work away from `main`. Incremental **Commits** capture atomic updates. The **Pull Request** connects the branch work back to the issue, facilitates peer/self-**review**, and safely merges the verified changes into the default branch upon approval
